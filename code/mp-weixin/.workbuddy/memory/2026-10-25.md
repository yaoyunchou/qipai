### 🔥🔥 根因确认（11:46）：账号是「开发者」不是「管理员」
用户最终确认：**账号角色是开发者，不是管理员。**

微信规则：**`upload`（上传代码包）必须管理员身份**；
纯「开发者」只能预览/调试，不能上传。

这解释了全部现象：
| 现象 | 解释 |
|---|---|
| `√ Using AppID: wxed679f2f2b6d353c` | CLI 能读配置打印 appid |
| 日志 `Fetching AppID () permissions` 括号为空 | **拉不到权限**（非管理员）|
| `41002 appid missing` | 上传接口要管理员凭证 → 拿不到 → 报 appid missing |
| `cli.bat auto` √ 成功 | 该命令不需要管理员权限 |
| order-center(wx029115c447f2662f) √ 上传成功 | 那个 appid 账号是管理员 |

⚠️ **`41002 appid missing` 极具欺骗性**：它说「appid 缺失」，但 appid 明明在
`project.config.json` 里、CLI 也打印出来了。真实含义是
「拿不到上传所需的 appid 凭证（管理员权限）」。
**排查时看到 41002，先查账号角色，别去查配置文件/工具/网络。**

⚠️ 第二个教训：**用户说「权限没问题」时，问的是「什么角色」而不是「有没有权限」。**
本次绕了很久就是因为把「有权限」理解成了「能上传」。

### 排查结论：CLI 上传通道本身是好的
对照组证明：同账号、同 CLI、同工具，order-center 上传 √ 成功。
所以问题从来不是工具故障、登录态、网络或代码。

**以后遇到上传失败，先做对照组实验**：
拿一个已知能传的项目跑同样的 `cli.bat upload`，
成功 → 问题在项目/账号侧；失败 → 才是工具问题。
这比反复重试快 10 倍。
用户扫码登录后重跑，仍报 `41002 appid missing`（与 10-09 完全同一个错）。

**翻日志找到真相**（`User Data\<profile>\WeappLog\logs\*.log`）：
- 10-09 **成功**那次，日志里有
  `[win-close-trace] native-window-close { winId: 'UPLOAD_DOWNLOAD_POPUP' ... }`
  → **上传是走 GUI 弹窗完成的**，`cli.bat upload` 当时只是旁路日志。
- 今天失败这次，请求带 `win:s1`（项目列表窗口），那个窗口没有 appid 上下文
  → 服务器收到空 appid → `41002 appid missing`
- 日志里 `Fetching AppID () permissions` 的 **appid 括号是空的**，
  但下一行照样打印 `√ Using AppID: wxed679f2f2b6d353c`（自相矛盾）

**尝试过且无效的方案**：
| 方案 | 结果 |
|---|---|
| `cli.bat upload` 重试 | 41002 |
| 显式加 `--appid wxed679f2f2b6d353c` | 41002（`--appid` 在给了 `--project` 时被忽略）|
| `cli.bat islogin` 判登录 | 误报 `{"login":true}`，不可信 |
| `cli.bat auto` 拿权限 | √ 成功，但 upload 仍 41002（两套通道）|

**结论**：这个 appid 的上传**必须走 GUI**（工具右上角「上传」按钮）。
CLI upload 在此appid 上不可靠，**以后遇到 41002 直接改走 GUI，不要反复重试 CLI**。

### 复用要点：换域名的完整检查清单
```bash
# 1. 域名可用性（必测 HTTPS 接口，不能只看首页）
curl -s --noproxy "*" -m 12 "https://<域名>/web/index.php?_mall_id=1&r=api/index/config"
# 2. 数副本（微擎通病：每个目录一份）
find . -name "siteinfo.js" -not -path "./node_modules/*"
# 3. 同步后校验一致性 + 残留
# 4. 备份 → 改根 → 同步全量 → node --check → 上传
```

⚠️ **服务端返回的静态资源 URL 域名 = 后端正主域名**。
看 `api/index/config` 返回里的 `web/statics/...` URL 指向哪个域名，
就知道微擎后台真正配的是哪个 —— 比猜准得多。
